## Подтверждённые находки

### F01 · P1 · DL-10 — исходник удаляется до создания замены

- Код: `internal/features/filemanager/service.go:1036–1050`; маршрут зарегистрирован в `internal/features/filemanager/feature.go`.
- Условие: `Redownload` с `delete_existing=true`, источник найден, постановка новой задачи возвращает ошибку.
- Ожидание: прежний файл остаётся до проверки и подтверждения замены. Факт: `DeleteFile` вызывается раньше `CreateJob`, файл уже отсутствует при ошибке очереди. Аналогично отмена/ошибка последующего скачивания не восстанавливает удалённое.
- Доказательство: `evidence/repro.log`, строка `redownload`, временный файл и заглушка очереди. Существующие тесты в `internal/api/e2e_user_journey_test.go:787` даже ожидают немедленное удаление: исторический PASS не подтверждает новое DL-10.
- Исправление отдельной задачей: staging замены, валидация результата, подтверждение, атомарное переключение с восстановлением. Проверка: сбои очереди, загрузчика, отмена и рестарт сохраняют исходник и companions.

### F02 · P1 · SEC-01, LIB-09 — удаление корня через алиас `./`

- Код: `internal/features/filemanager/service.go:493–520`, `ResolvePath:70–104`.
- Проверка запрещает только сырые `""`, `"."`, `"/"`; `"./"` проходит. `ResolvePath` допускает корень, затем `RemoveAll` удаляет его.
- Доказательство: воспроизведение `DeleteFile(ctx,"./")` вернуло успех и удалило корень временной библиотеки (`delete_root_alias` в логе). Пользовательские файлы не затрагивались.
- Ожидание: отказ для любого представления корня. Исправление: проверять канонический результат с запретом корня до удаления; отдельно тестировать `./`, `a/..`, URL-кодирование и абсолютные алиасы.

### F03 · P1 · SEC-01 — Resolve не защищает от подмены после проверки

- Код: `internal/core/sandbox/sandbox.go:97–124` возвращает строку; файловые операции выполняются позже, например `internal/features/filemanager/service.go:520` и `internal/id3/reader.go:21`.
- Условие: другой процесс/актор может менять каталог внутри разрешённого корня между Resolve и I/O. Это условная локальная атака; удалённая возможность создать симлинк через API не установлена.
- Доказательство: harness разрешает `dir/secret`, затем заменяет `dir` симлинком на соседнюю временную директорию; чтение ранее проверенного пути получает внешнюю фикстуру (`outside_read=true`).
- Исправление: операции относительно удерживаемого дескриптора корня с безопасной обработкой симлинков, а не повторная проверка строки. Проверять каждый производный путь companions и каждый элемент обхода. Приёмка: гонка подмены не читает/не изменяет внешний файл.

### F04 · P1 · DL-07 — ffmpeg выдаёт VBR вместо обязательного CBR

- Код: `internal/services/downloader/media_processor.go:138–150`: после `-b:a 320k` добавляется `-q:a 0`.
- Доказательство: синус 1 кГц длительностью 3 секунды с этими параметрами дал MP3/44100 Hz/**100268 bit/s**, см. `evidence/ffmpeg-q0.json`. Требуется 320000 bit/s CBR.
- Существующий `TestFfmpegArgs_320kbps` проверяет наличие аргументов, а `TestTranscodeToMP3_RealFFmpeg` — непустоту файла; оба проходят при нарушении.
- Исправление: убрать выбор VBR; добавить проверку фактических MP3-кадров/битрейта на нескольких синтетических сигналах и длительностях.

### F05 · P1 · SEC-03 — встроенный запасной ключ сессий

- Код: `internal/config/config.go:105–107`, `internal/core/auth/auth.go:42–71`, `internal/api/router.go:103`.
- При отсутствующем/пустом SECRET_KEY конфигурация использует константу из репозитория, а middleware принимает HMAC, вычисленный с этим ключом. В коде также есть запасной bcrypt-хэш. Значения здесь не дублируются.
- Доказательство статическое: `getEnv` выбирает fallback и Load не отвергает такую конфигурацию; middleware проверяет подпись и время, но не происхождение ключа. Безопасность конкретного развёртывания с собственным секретом не оценивалась.
- Исправление: fail-fast без обязательных секретов; тестировать пустое окружение без чтения рабочей .env. Не генерировать постоянный известный секрет автоматически.

### F06 · P1 · SEC-03, OPS-01 — Secure и настройки сессий не применяются

- Код: `internal/core/auth/auth.go:16,42–83`, `internal/api/handlers/auth_handlers.go:48–49`; поля конфигурации `SessionCookieSecure`, `SessionTTL`, `SessionCookieName` существуют, но вне config не используются.
- Доказательство: `session_cookie` в `repro.log` содержит HttpOnly и SameSite=Strict, но не Secure. Setter не получает ни request, ни config, поэтому HTTPS это не меняет. TTL и имя жёстко заданы.
- Ожидание: Secure при HTTPS и документированные настройки. Исправление: передавать эффективную политику cookie и TTL в auth; проверить HTTPS, доверенный reverse proxy и expiry. SameSite остаётся Strict.

### F07 · P1 · SEC-03, LIB-05 — OAuth state создаётся, но не проверяется

- Код: `internal/features/tageditor/handlers.go:338–346,368–389`, `internal/features/tageditor/service.go:1728–1752`; публичный callback — `internal/api/router.go:107`.
- Login создаёт state-cookie. Callback читает code и передаёт его в ExchangeCode без сравнения query state и cookie; сервис вообще не получает state.
- Статическое доказательство: отсутствующая/чужая state не меняет ветвь обработки code. Реальный обмен с MusicBrainz не выполнялся. Риск — привязка чужого OAuth-подключения через несвязанный callback.
- Исправление: проверять одноразовый state до обмена, ограничить срок, очищать после использования; тесты missing/mismatch/expired/replay не должны вызывать ExchangeCode. Lax для отдельной state-cookie допустим, основная сессия остаётся Strict.

### F08 · P1 · LIB-08, LIB-10 — потеря отличающегося companion при дедупликации

- Код: `internal/services/organizer/companions.go:49–56,92–105`.
- Условие: одинаковые MP3, разные LRC у источника и назначения. Аудиохэш совпадает; наличие целевого LRC достаточно для удаления исходного LRC без сравнения содержимого.
- Доказательство: `companion_collision` в логе — исходный уникальный текст исчез, назначение сохранило старый текст.
- Ожидание: конфликт либо сохранение обоих вариантов. Исправление: отдельное сравнение companions, план перемещения до удаления аудио, обработка ошибок и восстановление. Проверять также отказ переноса и коллизии обложек.

### F09 · P2 · OPS-02, качество — suite содержит live-сетевой тест

### F10 · P2 · OPS-02 — выбор цели ручного deploy не останавливает job

- Код: `.github/workflows/deploy.yml:103–110`.

- Статическое доказательство: условие ограничено одним step, matrix содержит обе цели. На серверы аудит не подключался.
- Исправление: фильтровать matrix либо все изменяющие шаги; проверить workflow_dispatch отдельно для каждой цели на фиктивных командах. Общая concurrency-группа есть; совместная блокировка с ручным `scripts/deploy.sh` не доказана.

### F11 · P1 · SYS-01, SYS-02 — текущая поставка yt-dlp требует Python

- Исправление: отдельно определить и задокументировать допустимый автономный yt-dlp и EJS-движок в рамках Zero-Node/Zero-Python; проверить итоговый PATH в unit systemd. Системную установку в ходе аудита не менять.

## Непроверенные условия и следующий этап

1. Реальный доступ к YouTube/YTM, SoundCloud, Deezer, Yandex, Spotify/Apple, LRCLIB/Genius, MusicBrainz/Shazam; cookies, геоблокировки, DRM, fallback и фактический EJS. Использование мока не означает приёмку поставщика.
2. Полный SSRF-аудит всех путей с DNS/redirect/rebinding. В `tageditor/service.go:951–969` и downloader загрузка обложек использует обычный http.Client; сквозная эксплуатация через публичный ввод не подтверждена, поэтому не включена как доказанная находка.
3. Жёсткие сбои процесса/диска между ФС и SQLite, идемпотентная приёмка, concurrent rename, ENOSPC/EXDEV; полнота обхода всех производных путей. `filesystem-calls.txt` — инвентаризация для продолжения, а не отметка проверки каждого вызова.
4. Браузер на 375×812, 423×919, 1280×800, реальные правки после сортировки/фильтра, keyboard/focus/контраст/скринридер, управление плеером/LRC. Скриншоты не получены, WCAG 2.2 AA не подтверждён. MOB остаётся предложением.
5. Полная таблица JSON/multipart/error контрактов против API.md/OpenAPI, публичный доступ к каждой комбинации alias/token/HEAD и токеновые утечки в логах. Инвентаризация маршрутов сохранена, полной контрактной приёмки нет.
6. BitTorrent: лимиты и отмена на фиктивном aria2; реальный Navidrome, повторная регистрация станции; качество радио 45/30/25 и дедупликация радара при аварии после постановки задачи.
7. Профиль нагрузки >2000 треков, параллельный аудит/сканирование/загрузка, latency/RSS и совместимость данных после rollback. Нагрузочные цифры не придуманы; безопасный запуск production и раскатка не выполнялись.
8. Полные обычный/race suite после мокирования live-тестов, все ID3 fuzz targets, проверка CVE и статический инвентарь секретов вне просмотренных мест.
