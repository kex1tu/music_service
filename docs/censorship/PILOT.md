# Пилот аудита цензуры

Пилот и массовая обработка пока НЕ выполнены: нужны реальные записи и ручная
разметка владельца. Синтетические тесты подтверждают механику, а не музыкальную
точность. Реальные запросы выполняются только явным запуском из интерфейса.

1. Подготовить 200 MP3 в отдельной песочнице. Включить оригиналы и цензурированные
   пары, темы наркотиков/суицида, другие замены, мат, музыкальные паузы,
   синтезаторные сигналы, обратное слово, ремастеры, неточные и отсутствующие LRC.
2. Вести внешний JSONL-манифест: song_id, relative_path, split (tune/evaluate),
   label (censored/original/ambiguous), events [{start,end,kind}], reference_path.
   Разделить 100/100 по song_id: версии одной песни не должны пересекать части.
3. Сначала запустить local, затем независимо Gemini и Deepgram на тех же файлах.
   Перед облаком проверить бесплатную квоту/кредит и задать дневной лимит секунд.
   Ключи добавить локально в .env, не передавать через команды/логи/репозиторий.
4. Сопоставлять результаты по событиям и трекам; считать precision, recall,
   ложные тревоги на оригиналах, долю insufficient_data, проверенные минуты,
   задержку и расход. Не исключать неоднозначные случаи из отчёта о покрытии.
5. Настраивать только на tune, один раз оценить evaluate; сохранить модель,
   конфигурацию и версию алгоритма. Расшифровка сама по себе не доказывает
   намеренность изменения и может восстанавливать неуслышанные слова.
6. После прослушивания небольшой партии решить, достаточно ли качества для
   очереди 11000 треков. До этого массовый режим остаётся сбором подозрений.
   Платный запуск согласуется отдельно после расчёта минут и тарифа.

Текущие ограничения: локальный детектор ищет тишину и узкополосные сигналы,
сравнение эталона — различия выровненных огибающих. Он не гарантирует обнаружение
перепетых или обращённых слов, не отделяет вокал от инструментала. Без пригодного
LRC выполняется локальное сканирование сигналов, облачная полная расшифровка
автоматически не запускается; это явно ограниченное покрытие.
