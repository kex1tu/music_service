## 1. Резюме исследования и суть архитектурного конфликта

### 1.1. Контекст
В рамках проекта Music Downloader & Tag Manager реализован импорт публичных метаданных Яндекс Музыки (треки, альбомы, плейлисты по URL и iframe) через клиент `internal/services/resolver/client_yandex.go`. Однако на этапе получения аудиофайла треки Яндекса в настоящий момент не имеют прямого источника аудиопотока (`AudioSourceURL == ""`) и требуют ручного сопоставления с альтернативными источниками (SoundCloud, YouTube Music) через окно выбора источников.

Цель настоящего исследования — оценить возможность прямого скачивания аудиопотока из инфраструктуры Яндекс Музыки в максимальном качестве (FLAC / High Quality) и сформировать архитектурный план интеграции.

### 1.2. Архитектурный конфликт (AGENTS.md §2.4 vs Прямой транспорт)
В соответствии с **AGENTS.md, раздел 2, пункт 4**:
> *«Аудио-пайплайн фиксирован. Скачивание — `yt-dlp`; конвертация — `ffmpeg` в MP3 320 kbps CBR / 44.1 kHz; теги — строго ID3v2.4 UTF-8 через внутренний пакет `internal/id3`...»*

**Выявленное противоречие:**
1. В изученном экстракторе `yt-dlp` отсутствует поддержка мобильной OAuth-авторизации, `/get-file-info` и AES-CTR. Локальный запрос к веб-эндпоинту завершился ошибкой TLS.
2. Рассматриваемый вариант прямого скачивания аудио — реализация **нативного Go HTTP-транспорта** с подписью запросов HMAC-SHA256 и потоковым дешифрованием AES-128-CTR.
3. Этот подход **напрямую нарушает жесткий инвариант AGENTS.md §2.4** («Скачивание — `yt-dlp`»).

**Решение на текущем этапе:** Код скачивания, криптография, production-конфигурация и whitelist доменов **не изменяются**. Настоящий документ фиксирует результаты технического анализа, формулирует проект интерфейсов и выносит конфликт на уровень владельца репозитория.

### 2.2. Анализ протокола по исходному коду (`ymd/api.py`, `ymd/core.py`)

#### Шаг 1: Получение ссылки и ключа дешифрования (`get_download_info`)
Запрос отправляется методом `GET` к эндпоинту:
`https://api.music.yandex.net/get-file-info`

**Обязательные параметры запроса:**
- `ts`: UNIX-таймштамп в секундах (`int(time.time())`).
- `trackId`: числовой идентификатор трека в каталоге Яндекса (строка/число).
- `quality`: целевое качество (`"lq"` — AAC 64 kbps, `"nq"` — MP3/AAC 192 kbps, `"lossless"` — FLAC 16-bit / 44.1 kHz).
- `codecs`: список поддерживаемых контейнеров/кодеков через запятую: `"flac,flac-mp4,mp3,aac,he-aac,aac-mp4,he-aac-mp4"`.
- `transports`: `"encraw"` (зашифрованный сырой аудиопоток).
- `sign`: HMAC-SHA256 подпись параметров запроса.

**Формирование цифровой подписи (`sign`):**
1. Значения параметров соединяются в одну строку в фиксированном порядке (`ts`, `trackId`, `quality`, `codecs`, `transports`), при этом из строки удаляются все запятые:
   ```python
   "".join(str(e) for e in params.values()).replace(",", "").encode()
   ```
2. Вычисляется HMAC-SHA256 от сформированной строки с использованием встроенного клиентского ключа подписи (происхождение: официальный Android-клиент Яндекс Музыки, в библиотеке `yandex_music` обозначен как `DEFAULT_SIGN_KEY`).
3. Результат кодируется в Base64, после чего отсекается последний символ (padding):
   ```python
   sign = base64.b64encode(hmac_sign.digest()).decode()[:-1]
   ```

**Авторизация:**
Запрос требует HTTP-заголовка `Authorization: OAuth <token>`. Без авторизационного токена эндпоинт возвращает HTTP 401 Unauthorized либо ограничивает доступ коротким фрагментом (превью).

#### Шаг 2: Структура ответа `downloadInfo`
API возвращает JSON-документ следующего вида:
```json
{
  "invocationInfo": { ... },
  "downloadInfo": {
    "codec": "flac",
    "quality": "lossless",
    "bitrate": 0,
    "urls": [
      "https://storage.yandex.net/get-mp3/...",
      "https://streaming.yandex.net/get-mp3/..."
    ],
    "key": "0123456789abcdef0123456789abcdef"
  }
}
```
- `urls`: массив прямых временных CDN-ссылок на зашифрованный файл. Ссылки содержат подписанные токены доступа с ограниченным сроком жизни (обычно 15–60 минут).
- `key`: 16-байтный (128-битный) ключ дешифрования в виде 32-символьной hex-строки (присутствует при `transports=encraw`).

#### Шаг 3: Потоковое дешифрование аудио (`decrypt_data`)
- **Алгоритм:** AES-128 в режиме CTR (Counter mode).
- **Ключ:** `bytes.fromhex(download_info.decryption_key)` (16 байт).
- **Вектор инициализации (IV / Nonce):** В исходниках `ymd/api.py` передается `nonce=bytes(12)` при стандартном 4-байтном счетчике, начинающемся с нуля. В терминах стандартного 16-байтного блока AES-CTR это эквивалентно **16 нулевым байтам** (`0x00 * 16`).
- **Операция:** Байты зашифрованного потока подвергаются операции XOR с гаммой AES-128 (`stream.XORKeyStream`). Результатом является валидный аудиопоток (FLAC или MP3/AAC), готовый к обработке через `ffmpeg`.

### 2.3. Граница между подтверждённым кодом и предположениями
- **Подтверждено исходным кодом стороннего клиента:**
  - Наличие и структура эндпоинта `https://api.music.yandex.net/get-file-info`.
  - Алгоритм формирования подписи HMAC-SHA256 и формат параметров `transports=encraw`.
  - Корректность расшифровки AES-128-CTR с нулевым 16-байтным IV/счетчиком.
- **Предположения и эксплуатационные риски (не гарантировано API):**
  - Доступность полного трека и FLAC для разных аккаунтов, подписок и регионов требует отдельной проверки с авторизацией.
  - Ключи подписи (`DEFAULT_SIGN_KEY`) могут быть отозваны или ротированы сервером при обновлении мобильных клиентов.
  - Сервер может внедрить проверку Google Play Integrity / SafetyNet / DeviceCheck для мобильных токенов.
  - Географическая доступность: доступ с конкретных IP и из разных регионов требует отдельной проверки.

## 3. Проверка возможностей локального `yt-dlp`

### 3.1. Версия и среда исполнения
- **Локальная версия `yt-dlp`:** `2026.08.19`. Проверенный файл в PATH является Python-скриптом.
- **Исходный файл экстрактора:** `yt_dlp/extractor/yandexmusic.py`. Production standalone ELF требует отдельной проверки.
- **Зарегистрированные экстракторы:**
  - `yandexmusic:album`
  - `yandexmusic:artist:albums`
  - `yandexmusic:artist:tracks`
  - `yandexmusic:playlist`
  - `yandexmusic:track`

### 3.2. Архитектура экстрактора `yandexmusic` в `yt-dlp`
Анализ исходного кода `yandexmusic.py` выявил критические ограничения:
1. **Отсутствие авторизации по токену:** В экстракторе `YandexMusicBaseIE` нет поддержки OAuth-токенов (`--token`), логинов/паролей или заголовков авторизации API. Доступна только передача браузерных cookies (`--cookies`), которые в настоящее время не поддерживают авторизацию мобильного API (подтверждено в `MIGRATION.md` проекта `yandex-music-downloader`: «авторизация через cookies невозможна»).
2. **Использование устаревшего веб-эндпоинта:**
   Для получения ссылки на аудио `yt-dlp` обращается к веб-хендлеру:
   `https://music.yandex.ru/api/v2.1/handlers/track/{track_id}:{album_id}/web-album_track-track-track-main/download/m?hq=1`
   и рассчитывает MD5-хэш по параметрам веб-ответа.
   Формируемый URL: `http://{host}/get-mp3/{key}/{ts}{path}?track-id={id}`.
3. **Отсутствие поддержки защищенных потоков и FLAC:**
   `yt-dlp` вообще не имеет реализации для `/get-file-info`, не умеет запрашивать `transports=encraw` и не содержит логики дешифрования AES-128-CTR.
4. **Локальная ошибка TLS:**
   При локальном вызове `yt-dlp` к `music.yandex.ru`:
   ```bash
   yt-dlp --dump-json --no-download "https://music.yandex.ru/album/540508/track/4878838"
   ```
   Происходит немедленный сбой:
   ```text
   WARNING: [yandexmusic:track] 4878838: Unable to download JSON metadata: [SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol (_ssl.c:1000)
   ERROR: argument of type 'bool' is not iterable
   ```
   Локальная диагностика зафиксировала ошибки TLS (`SSL_ERROR_SYSCALL` / `UNEXPECTED_EOF_WHILE_READING`). Эти сообщения не определяют причину сброса соединения.

### 3.3. Вывод по `yt-dlp`
В изученной версии веб-экстрактор не использует мобильный протокол. Локальный вызов не подтвердил получение аудио, а результат для production ELF и авторизованных аккаунтов остаётся открытым.

## 4. Сравнительный анализ вариантов реализации

| Критерий | Вариант 1: Штатный `yt-dlp` | Вариант 2: Нативный Go Transport (`encraw` + AES) |
|---|---|---|
| **Работоспособность в production** | Локально наблюдалась ошибка TLS | Не проверено с авторизацией |
| **Поддерживаемое качество** | Максимум 192 kbps MP3 (если бы работал веб-хендлер) | **FLAC (Lossless 16-bit / 44.1 kHz)** или AAC 192/320 kbps |
| **Авторизация** | Только cookies (устарели и не принимаются API) | **OAuth-токен мобильного клиента** (`Authorization: OAuth`) |
| **Шифрование аудио** | Не поддерживается | **AES-128-CTR** (стандартный пакет Go `crypto/aes`, `crypto/cipher`) |
| **Подпись запросов** | Устаревший MD5 хэш веб-интерфейса | **HMAC-SHA256** (стандартный пакет Go `crypto/hmac`, `crypto/sha256`) |
| **Соответствие AGENTS.md §2.4** | Соответствует инварианту | **Конфликт**: скачивание в обход `yt-dlp` запрещено инвариантом §2.4 |
| **Внешние зависимости** | Требует Python-скрипт/бинарник `yt-dlp` | **Pure Go**: ноль внешних runtime-зависимостей, единый бинарник |
| **Стабильность сети** | Локально наблюдалась ошибка TLS | Требует проверки на целевых серверах |

## 5. Условия доступа и требования безопасности

1. **Авторизационный токен:**
   - Требуется OAuth-токен аккаунта с активной подпиской «Яндекс Плюс».
   - Способ получения токена пользователем: официальный Implicit Flow (Яндекс OAuth) через утилиты извлечения токенов (например, `ym.marshal.dev/token/#implicit-oauth`).
   - Сервис `music-manager` **ни при каких условиях** не должен запрашивать, сохранять или логировать логины и пароли пользователей от Яндекс ID. В конфигурацию передается только готовый токен через переменную окружения `YANDEX_MUSIC_TOKEN`.
2. **Отсутствие гарантий скорости и вечной подписки:**
   - Сервис не может гарантировать работу без активной подписки или обход платного доступа.
   - При истечении подписки или невалидном токене API возвращает HTTP 403 Forbidden.
3. **Географические ограничения и Proxy:**
   - Доступность API на целевых серверах и причины возможного HTTP 451 требуют отдельной проверки.
   - Для Яндекс-клиента в проекте уже есть опциональная настройка `YANDEX_MUSIC_PROXY`.
   - Прокси должен применяться как к запросам метаданных, так и к вызовам `/get-file-info` и скачиванию аудиопотоков из CDN Яндекса.
4. **Конфиденциальность ключей и подписей:**
   - В коде и документации **запрещено публиковать реальные значения встроенных секретных ключей**. Значение клиентского ключа подписи должно передаваться через константу сборки или конфигурацию.

## 6. Архитектурный дизайн интеграции (Go Transport)

### 6.1. Разделение каталожной сущности и временного аудиопотока

Для обеспечения отказоустойчивости, изоляции секретов и выживаемости при перезапуске сервиса вводится строгое разделение сущностей:

```
┌────────────────────────────────────────────────────────────────────────┐
│                   КАТАЛОЖНАЯ СУЩНОСТЬ (Persistent)                     │
│  - CatalogTrackID: "ya_6705392"                                        │

│  - Хранение: SQLite (download_jobs, job_tracks, library tracks)        │
│  - Логирование: Разрешено, безопасно                                   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Разрешение перед стартом потока
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   ЭФЕМЕРНЫЙ ПОТОК (Ephemeral in-memory)                │
│  - DirectCDNURL: "https://storage.yandex.net/get-mp3/...?ts=..."       │
│  - AES128Key: []byte (16 байт)                                         │
│  - Срок жизни: 15-60 минут (TTL токена хранилища)                      │
│  - Хранение: ТОЛЬКО в RAM во время выполнения горутины                 │
│  - Логирование: СТРОГО ЗАПРЕЩЕНО (маскирование URL и ключа)            │
│  - Поведение при рестарте: Повторный запрос /get-file-info             │
└────────────────────────────────────────────────────────────────────────┘
```

### 6.2. Предлагаемые интерфейсы Go

#### 1. Клиент информации о файле (`internal/services/resolver/client_yandex.go`)
```go
// YandexDownloadInfo содержит эфемерные параметры для скачивания и дешифрования аудиопотока.
type YandexDownloadInfo struct {
    Codec         string   `json:"codec"`          // "flac", "mp3", "aac"
    Quality       string   `json:"quality"`        // "lossless", "nq", "lq"
    Bitrate       int      `json:"bitrate"`        // битрейт в kbps
    URLs          []string `json:"urls"`           // список зеркал CDN
    DecryptionKey []byte   `json:"-"`              // 16 байт распарсенного AES ключа (не сериализуется в JSON)
    ExpiresAt     time.Time `json:"-"`             // расчетный срок жизни ссылки
}

// GetDownloadInfo запрашивает эфемерные URL и ключ дешифрования для трека.
func (c *YandexMusicClient) GetDownloadInfo(ctx context.Context, trackID int64, quality string) (*YandexDownloadInfo, error)
```

#### 2. Потоковый дешифратор (`internal/services/downloader/yandex_decryptor.go`)
```go
// NewYandexDecryptingReader оборачивает сетевой поток io.Reader, расшифровывая его на лету через AES-128-CTR.
func NewYandexDecryptingReader(src io.Reader, key []byte) (io.Reader, error) {
    if len(key) != 16 {
        return nil, errors.New("invalid AES-128 key length")
    }
    block, err := aes.NewCipher(key)
    if err != nil {
        return nil, fmt.Errorf("failed to create AES cipher: %w", err)
    }
    // 16 нулевых байтов в качестве начального вектора и счетчика
    iv := make([]byte, aes.BlockSize)
    stream := cipher.NewCTR(block, iv)
    return &cipher.StreamReader{S: stream, R: src}, nil
}
```

#### 3. Сервисный загрузчик потока (`internal/services/downloader/yandex_streamer.go`)
```go
// DownloadYandexStream выполняет потоковое скачивание, дешифрование и сохранение в staging.
func (s *Service) downloadYandexStream(
    ctx context.Context,
    trackID int64,
    outPath string,
    progressFn func(pct float64),
) (string, error)
```

### 6.3. Интеграция в жизненный цикл и Staging

1. **Staging изоляция:**
   - Поток скачивается во временный файл: `tmp_downloads/{job_id}/raw/{track_idx}_track.flac.tmp` через `safefs` и `PathSandbox.Resolve()`.
   - Запись выполняется чанками (буфер 64 КБ). При каждом прочитанном блоке обновляется монотонный прогресс задачи в `JobManager`.
   - В случае успешного завершения файл атомарно переименовывается в `tmp_downloads/{job_id}/raw/{track_idx}_track.flac`.
2. **Обработка отмены и сбоев:**
   - При отмене контекста (`ctx.Done()`) или ошибке сети временный файл `.tmp` немедленно удаляется через `safefs.Remove()`.
   - Частично скачанный файл **никогда не может получить статус ready**.
3. **Завершение через штатный аудио-пайплайн:**
   - Полученный расшифрованный файл (FLAC или High-Bitrate AAC/MP3) передается в штатный транскодер:
     ```bash
     ffmpeg -i raw/{track_idx}_track.flac -codec:a libmp3lame -b:a 320k -ar 44100 converted/{track_idx}_{title}.mp3
     ```
   - Записываются ID3v2.4 UTF-8 теги через `internal/id3` с разделителями `\x00`.
   - Синхронизированный текст песни сохраняется во внешний companion `.lrc` файл.
   - Оригинальная обложка сохраняется как `cover.jpg` и вшивается в APIC.
   - Перенос в медиатеку `MUSIC_DIR` выполняется строго через `organizer.Service` после валидации пользователем.

## 7. Политика ошибок и запрет скрытых фолбэков

В соответствии с правилами проекта:
- **Запрет тихого фолбэка:** Если прямое скачивание Яндекс Музыки завершилось ошибкой (например, 401/403 из-за невалидного токена, 451 из-за отказа прокси, 404 для трека, изъятого правообладателем), система **не имеет права** автоматически и молча переключать источник на YouTube Music или SoundCloud.
- **Ожидание источника:** Трек переводится в статус `waiting_source` с понятным описанием ошибки в интерфейсе («Требуется авторизация Яндекс Плюс», «Ошибка прокси РФ/СНГ», «Трек недоступен в регионе»). Пользователь может вручную выбрать альтернативный источник через окно выбора версий.

## 8. Затрагиваемые области кодовой базы

В случае одобрения владельцем проекта перехода на нативный Go Transport потребуются изменения в следующих модулях:

1. **`internal/config/`**:
   - Добавление `YANDEX_MUSIC_TOKEN` (строка, токен авторизации).
   - Добавление `YANDEX_MUSIC_PROXY` (строка, URL прокси для обхода гео-ограничений).
   - Добавление флага `YANDEX_DIRECT_DOWNLOAD_ENABLED` (boolean, по умолчанию `false`).
   - Обновление `.env.example` (без реальных секретов).
2. **`internal/services/resolver/`**:
   - Реализация метода `GetDownloadInfo` в `client_yandex.go`.
   - Реализация расчета подписи HMAC-SHA256 параметров `ts`, `trackId`, `quality`, `codecs`, `transports`.
   - Парсинг ответа `/get-file-info` и извлечение шестнадцатеричного ключа дешифрования.
3. **`internal/services/downloader/` и `internal/features/downloader/`**:
   - Добавление `yandex_streamer.go` и `yandex_decryptor.go` с потоковым AES-128-CTR дешифрованием через `cipher.StreamReader`.
   - Интеграция в `processSingleTrack`: ветвление по схеме источника `ya_*` / `yandex` на вызов нативного стримера вместо вызова `downloadRawStream(yt-dlp)`.
   - Гарантия неизменности последующих шагов: валидация битрейта, транскодирование ffmpeg в MP3 320k CBR / 44.1 kHz, тегирование ID3v2.4 UTF-8, создание companion `.lrc`.
4. **`internal/api/` / UI**:
   - Отображение статуса доступности прямого источника Яндекс Музыки (активен ли токен).

## 9. План тестирования и верификации

1. **Криптографические unit-тесты (`yandex_crypto_test.go`):**
   - Тест вычисления HMAC-SHA256 подписи на эталонном векторе параметров (фиксированный timestamp, trackId, codecs, ключ).
   - Тест потокового дешифратора AES-128-CTR: зашифрование известного тестового FLAC-заголовка (`fLaC`) тестовым ключом и нулевым IV, последующая расшифровка через `NewYandexDecryptingReader` и побайтовое сравнение с эталоном.
2. **Mock HTTP-тесты клиента (`client_yandex_download_test.go`):**
   - Тест успешного ответа `/get-file-info` с парсингом URL и hex-ключа.
   - Тесты обработки кодов ошибок:
     - HTTP 401 / 403: ошибка авторизации / отсутствие подписки Плюс.
     - HTTP 404: трек изъят из каталога.
     - HTTP 429: срабатывание rate limit.
     - HTTP 451: гео-блокировка (сообщение о необходимости `YANDEX_MUSIC_PROXY`).
3. **Интеграционные тесты пайплайна (`yandex_pipeline_test.go`):**
   - Запуск `httptest.Server`, имитирующего CDN Яндекса с отдачей зашифрованного FLAC-потока.
   - Прогон полного пайплайна: стриминг → дешифрование на лету → сохранение в staging → вызов ffmpeg → запись ID3v2.4 → проверка целостности результирующего MP3 320 kbps.
   - Все сетевые вызовы в тестах строго замоканы (100% изоляция от внешнего интернета).

## 10. Минимальное архитектурное решение, требуемое от владельца проекта

Для перехода от этапа исследования к реализации прямого скачивания владелец проекта должен принять одно из двух решений:

- **Вариант А (Рекомендуемый): Внесение исключения в AGENTS.md §2.4.**
  Формулировка изменения:
  > *«Скачивание аудио производится через `yt-dlp`. Для защищенных каталожных источников, в которых `yt-dlp` не поддерживает авторизацию или шифрование потоков (Яндекс Музыка API), разрешается использование нативного Go HTTP-транспорта с потоковым дешифрованием AES-128-CTR при сохранении обязательного последующего пайплайна ffmpeg (MP3 320k CBR / 44.1 kHz) и ID3v2.4.»*
- **Вариант Б (Сохранение текущего статуса-кво): Отказ от прямого скачивания аудио Яндекса.**
  Яндекс Музыка используется исключительно как источник богатых каталожных метаданных, плейлистов и текстов песен. Аудиопотоки для треков Яндекса продолжают подбираться через SoundCloud-first / YouTube Music аудио-матчер либо выбираются пользователем вручную.
