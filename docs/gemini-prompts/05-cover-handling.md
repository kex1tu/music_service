# Промпт 5. Надёжная обработка обложек и оригиналы Яндекса

## Правила выполнения

Работай в существующем Music Downloader & Tag Manager. Этот промпт самостоятельный: предыдущая переписка и выполнение остальных промптов не предполагаются.

Перед изменениями прочитай AGENTS.md, Architecture.md, plan.md и последние записи PROGRESS.md. Проверь git status и diff; сохрани чужие незакоммиченные изменения. Открой затрагиваемые файлы и сигнатуры вызываемых методов. Сначала установи, что уже реализовано: указанные ниже точки входа отражают состояние на 9 ноября 2026 года и требуют повторной проверки.

Реализуй только описанную фичу. Обоснуй необходимые изменения смежных областей отдельной записью в plan.md, сохранив остальные планы. Соблюдай Pure Go, отсутствие Node/npm/Python в runtime и Docker, скачивание через yt-dlp, штатную конвертацию ffmpeg в MP3 320 kbps CBR / 44.1 kHz и внутренний ID3v2.4 UTF-8 с null-разделителями. Тексты — только внешние .lrc/.txt. Файловые операции — через PathSandbox.Resolve и существующие safefs/mediaexec; не ослабляй защиту от подмены путей. Итоговые файлы до подтверждения остаются в staging, переносит их organizer.

Не выполняй деплой, коммиты, push и массовые операции с медиатекой. Не используй реальные секреты в коде, фикстурах и логах. Новые настройки отражай в .env.example только при необходимости, без реальных значений. Не делегируй эту же задачу рекурсивно самому себе.

Все внешние HTTP-вызовы в автоматических тестах замокай. Для изменённого кода выполни целевые проверки, затем из корня проекта:

```bash
go test -v ./...
go test -race -p 1 ./...
go vet ./...
CGO_ENABLED=0 go build -ldflags="-s -w" -o bin/music-manager cmd/server/main.go
git diff --check
```

Не ослабляй тесты ради прохождения. Зафиксируй исходные сбои и ограничения среды. Обнови PROGRESS.md: что реализовано, что проверено и что заблокировано. В финале перечисли изменения с файлами, результаты команд, ограничения и непроверенное поведение. Успешные mock-тесты не доказывают доступность внешнего API в production.

## Задача

Улучши существующую обработку обложек: проверь ограничения ресурсов и итогового APIC, а для Яндекса добавь получение оригинального изображения с fallback, если протокол подтверждён.

Справочные идеи: https://github.com/megapro17/zvukdown и https://github.com/llistochek/yandex-music-downloader . Используй собственную реализацию; проверь лицензии перед любым заимствованием. pingo/ImageMagick и Python не добавляй.

## Исходное состояние

internal/id3/cover_optimize.go уже содержит OptimizeCoverForID3, вызываемую из internal/id3/writer.go. В internal/services/resolver/client_yandex.go BestCoverURL подставляет 1000x1000. Проверь эти места и действительные пути HTTP-загрузки обложек.

## Реализация

1. Сохрани один механизм оптимизации APIC и найди все пути его использования.
2. Ограничь сетевой ответ до чтения всего изображения; проверь максимальные измерения/число пикселей до полного декодирования. Учитывай некорректный Content-Length и переполнение при расчёте площади.
3. Если нужен жёсткий бюджет APIC в байтах, задай документированную константу и добейся соблюдения через существующую обработку: одного ограничения 1000 px недостаточно. Не меняй настройки всего приложения без необходимости.
4. Определи поведение для повреждённого, неподдерживаемого и чрезмерно большого изображения. Не допускай обхода ограничений возвратом исходного огромного среза при ошибке.
5. Подтверди поддержку оригинала Яндекса по актуальным исходникам. Если она есть, используй ограниченную загрузку оригинала с fallback на текущий вариант 1000x1000. Сохрани совместимость существующих вызовов BestCoverURL.
6. Разделяй оригинальное изображение и оптимизированный APIC. Отдельный cover.jpg сохраняй только при необходимости действующего пользовательского сценария и через sandbox; не создавай новую схему альбомных файлов автоматически.
7. При ошибке обложки сохрани штатную возможность завершить загрузку аудио без изображения, с понятным сообщением. Отмену задания соблюдай.
8. Не передавай авторизационные заголовки на посторонние хосты. Не меняй содержимое ранее сохранённых пользовательских обложек массово.

## Приёмка

Проверь JPEG/PNG, маленькое изображение без лишнего перекодирования, большое изображение, повреждённый вход, огромные объявленные измерения, превышение сетевого бюджета, fallback оригинал → 1000x1000 и отказ обеих ссылок. Подтверди валидный MIME, декодируемый APIC и соблюдение заданных ограничений. Сетевые тесты — только mock.

Если оригинальный endpoint не подтверждён, заверши независимые улучшения обработки и явно отметь ограничение. Не объявляй уже существующее масштабирование новой фичей.
