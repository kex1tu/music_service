# Промпт 3. Официальные LRC-тексты Яндекса с fallback

## Правила выполнения

Работай в существующем Music Downloader & Tag Manager. Этот промпт самостоятельный: предыдущая переписка и выполнение остальных промптов не предполагаются.

Перед изменениями прочитай AGENTS.md, Architecture.md, plan.md и последние записи PROGRESS.md. Проверь git status и diff; сохрани чужие незакоммиченные изменения. Открой затрагиваемые файлы и сигнатуры вызываемых методов. Сначала установи, что уже реализовано: указанные ниже точки входа отражают состояние на 9 ноября 2026 года и требуют повторной проверки.

Реализуй только описанную фичу. Обоснуй необходимые изменения смежных областей отдельной записью в plan.md, сохранив остальные планы. Соблюдай Pure Go, отсутствие Node/npm/Python в runtime и Docker, скачивание через yt-dlp, штатную конвертацию ffmpeg в MP3 320 kbps CBR / 44.1 kHz и внутренний ID3v2.4 UTF-8 с null-разделителями. Тексты — только внешние .lrc/.txt. Файловые операции — через PathSandbox.Resolve и существующие safefs/mediaexec; не ослабляй защиту от подмены путей. Итоговые файлы до подтверждения остаются в staging, переносит их organizer.

Не выполняй деплой, коммиты, push и массовые операции с медиатекой. Не используй реальные секреты в коде, фикстурах и логах. Новые настройки отражай в .env.example только при необходимости, без реальных значений. Не делегируй эту же задачу рекурсивно самому себе.

Все внешние HTTP-вызовы в автоматических тестах замокай. Для изменённого кода выполни целевые проверки, затем из корня проекта:

```bash
go test -v ./...
go test -race -p 1 ./...
go vet ./...
CGO_ENABLED=0 go build -ldflags="-s -w" -o bin/music-manager cmd/server/main.go
git diff --check
```

Не ослабляй тесты ради прохождения. Зафиксируй исходные сбои и ограничения среды. Обнови PROGRESS.md: что реализовано, что проверено и что заблокировано. В финале перечисли изменения с файлами, результаты команд, ограничения и непроверенное поведение. Успешные mock-тесты не доказывают доступность внешнего API в production.

## Задача

Добавь получение официального текста Яндекса по точному каталожному ID и подключи его перед действующей цепочкой поиска текстов. Ошибки провайдера не должны срывать скачивание аудио.

Справочный репозиторий: https://github.com/llistochek/yandex-music-downloader . Проверь commit, лицензию и фактический протокол получения lyrics, включая авторизацию/подпись и выдачу ссылки на текст. Не считай endpoint из прежнего анализа подтверждённой спецификацией.

## Точки входа

internal/services/lyrics/lyrics.go, internal/services/resolver/client_yandex.go, модель ResolvedTrack, оба действующих пути загрузки, сборка зависимостей в cmd/server/main.go.

Существующий LyricsProvider.Search принимает artist/title/album/duration, но не ID источника. Поддержка плейлистов из другого задания не является обязательной: фича должна работать для уже поддерживаемых треков/альбомов Яндекса.

## Реализация

1. Передавай точный Яндекс-ID от resolver до запроса текста. Не бери первый нечёткий результат поиска и не трактуй чужой TrackID как идентификатор Яндекса.
2. Выбери минимальное совместимое расширение: необязательный контекст источника или отдельный точный метод. Сохрани старые SearchLyrics-вызовы и тестовое внедрение провайдера. Избегай циклических импортов.
3. При необходимости сохрани идентичность источника в существующей persistence очереди и восстанови после рестарта. Старые задания без ID должны продолжать работать через прежний поиск.
4. При наличии точного ID сначала пробуй Яндекс, затем действующую цепочку провайдеров. Проверь её реальный состав. Без ID или токена не выполняй бессмысленные запросы.
5. Разделяй отсутствие текста, ошибку доступа, таймаут и отмену контекста. После отмены не продолжай fallback. Ограничь HTTP-ответ и число повторов.
6. URL текста и редиректы валидируй по существующей политике внешних запросов; OAuth-токен не должен уходить на посторонний хост.
7. Отличай LRC от обычного текста и HTML/JSON ошибок. Сохраняй .lrc/.txt существующим механизмом, обеспечив перенос companions и сохранность пользовательского текста. Поиск сам по себе файлов не пишет.
8. Не добавляй USLT/SYLT и другие фреймы с текстами. Не меняй аудиоисточник.
9. Не обещай процент покрытия. Непроверенную доступность API укажи отдельно.

## Приёмка

Mock-тесты точного ID, отсутствия ID/токена, LRC/plain text, пустого/повреждённого/слишком большого ответа, ошибок, отмены и fallback. Проверка интеграции обоих путей загрузки, восстановления очереди, сохранения и переноса внешнего текста. Подтверди отсутствие текста в записанном ID3.

Не включай плейлисты, прямые потоки и переделку общего matcher.
