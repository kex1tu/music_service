# Промпт 1. Безопасная длина имён файлов и каталогов

## Правила выполнения

Работай в существующем Music Downloader & Tag Manager. Этот промпт самостоятельный: предыдущая переписка и выполнение остальных промптов не предполагаются.

Перед изменениями прочитай AGENTS.md, Architecture.md, plan.md и последние записи PROGRESS.md. Проверь git status и diff; сохрани чужие незакоммиченные изменения. Открой затрагиваемые файлы и сигнатуры вызываемых методов. Сначала установи, что уже реализовано: указанные ниже точки входа отражают состояние на 9 ноября 2026 года и требуют повторной проверки.

Реализуй только описанную фичу. Обоснуй необходимые изменения смежных областей отдельной записью в plan.md, сохранив остальные планы. Соблюдай Pure Go, отсутствие Node/npm/Python в runtime и Docker, скачивание через yt-dlp, штатную конвертацию ffmpeg в MP3 320 kbps CBR / 44.1 kHz и внутренний ID3v2.4 UTF-8 с null-разделителями. Тексты — только внешние .lrc/.txt. Файловые операции — через PathSandbox.Resolve и существующие safefs/mediaexec; не ослабляй защиту от подмены путей. Итоговые файлы до подтверждения остаются в staging, переносит их organizer.

Не выполняй деплой, коммиты, push и массовые операции с медиатекой. Не используй реальные секреты в коде, фикстурах и логах. Новые настройки отражай в .env.example только при необходимости, без реальных значений. Не делегируй эту же задачу рекурсивно самому себе.

Все внешние HTTP-вызовы в автоматических тестах замокай. Для изменённого кода выполни целевые проверки, затем из корня проекта:

```bash
go test -v ./...
go test -race -p 1 ./...
go vet ./...
CGO_ENABLED=0 go build -ldflags="-s -w" -o bin/music-manager cmd/server/main.go
git diff --check
```

Не ослабляй тесты ради прохождения. Зафиксируй исходные сбои и ограничения среды. Обнови PROGRESS.md: что реализовано, что проверено и что заблокировано. В финале перечисли изменения с файлами, результаты команд, ограничения и непроверенное поведение. Успешные mock-тесты не доказывают доступность внешнего API в production.

## Задача

Устрани ошибки ENAMETOOLONG при длинных названиях на кириллице и emoji, сохранив текущие правила организации медиатеки.

Основная точка входа — internal/services/organizer/path.go и её вызовы. Сейчас SanitizeComponent ограничивает длину по числу рун; итоговое имя каталога собирается из нескольких частей. Проверь также имена staging и суффиксы коллизий.

## Реализация

1. Добавь небольшую функцию усечения строки по байтовому бюджету UTF-8 без разрыва рун. Размести её рядом с формированием имён; PathSandbox.Resolve не должен автоматически менять клиентский путь.
2. Сохрани смысл существующего параметра maxLength и поведение коротких имён. Байтовый лимит добавь отдельно.
3. Ограничивай полный компонент после сборки: каталог «альбом - исполнитель», имя с номером трека, разделителями, расширением и суффиксом коллизии. Документируй бюджет не более 255 байт для текущей Linux-цели и резерв под дополнительные части.
4. Обработай пустой результат, длинный fallback, малый бюджет, завершающие точки/пробелы, расширение .mp3 и многодисковые/дублирующиеся названия. Невозможный бюджет должен иметь определённое поведение.
5. После усечения разные файлы не должны молча перезаписываться. Используй существующую обработку коллизий; при добавлении суффикса пересчитывай бюджет.
6. Сохрани согласованное именование и перемещение .lrc/.txt/изображений через существующие companions. Старую медиатеку массово не переименовывай.

## Приёмка

Добавь проверки длинной кириллицы, ASCII, emoji, граничных бюджетов, каталога из двух длинных частей, длинного fallback и коллизий после усечения. Каждый сформированный компонент — валидный UTF-8 в установленном бюджете. Короткие имена остаются прежними. Компонентный тест в отдельном временном sandbox подтверждает создание и перенос аудио с companions без потери или перезаписи данных.

Другие фичи, внешние API, фронтенд и настройки формата аудио не меняй.
