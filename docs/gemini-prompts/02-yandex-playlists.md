# Промпт 2. Импорт публичных плейлистов Яндекс Музыки

## Правила выполнения

Работай в существующем Music Downloader & Tag Manager. Этот промпт самостоятельный: предыдущая переписка и выполнение остальных промптов не предполагаются.

Перед изменениями прочитай AGENTS.md, Architecture.md, plan.md и последние записи PROGRESS.md. Проверь git status и diff; сохрани чужие незакоммиченные изменения. Открой затрагиваемые файлы и сигнатуры вызываемых методов. Сначала установи, что уже реализовано: указанные ниже точки входа отражают состояние на 9 ноября 2026 года и требуют повторной проверки.

Реализуй только описанную фичу. Обоснуй необходимые изменения смежных областей отдельной записью в plan.md, сохранив остальные планы. Соблюдай Pure Go, отсутствие Node/npm/Python в runtime и Docker, скачивание через yt-dlp, штатную конвертацию ffmpeg в MP3 320 kbps CBR / 44.1 kHz и внутренний ID3v2.4 UTF-8 с null-разделителями. Тексты — только внешние .lrc/.txt. Файловые операции — через PathSandbox.Resolve и существующие safefs/mediaexec; не ослабляй защиту от подмены путей. Итоговые файлы до подтверждения остаются в staging, переносит их organizer.

Не выполняй деплой, коммиты, push и массовые операции с медиатекой. Не используй реальные секреты в коде, фикстурах и логах. Новые настройки отражай в .env.example только при необходимости, без реальных значений. Не делегируй эту же задачу рекурсивно самому себе.

Все внешние HTTP-вызовы в автоматических тестах замокай. Для изменённого кода выполни целевые проверки, затем из корня проекта:

```bash
go test -v ./...
go test -race -p 1 ./...
go vet ./...
CGO_ENABLED=0 go build -ldflags="-s -w" -o bin/music-manager cmd/server/main.go
git diff --check
```

Не ослабляй тесты ради прохождения. Зафиксируй исходные сбои и ограничения среды. Обнови PROGRESS.md: что реализовано, что проверено и что заблокировано. В финале перечисли изменения с файлами, результаты команд, ограничения и непроверенное поведение. Успешные mock-тесты не доказывают доступность внешнего API в production.

## Задача

Добавь импорт публичного плейлиста Яндекс Музыки по URL или iframe-коду в существующие предпросмотр и очередь. Импорт получает метаданные; скачивание остаётся в штатном пользовательском сценарии.

Справочный репозиторий: https://github.com/R3DCyclops/mp3_PLRKLR . Проверь актуальные исходники, commit и лицензию, не копируй код с несовместимыми условиями. Не добавляй Hitmo/Lmusic и их парсеры.

## Точки входа

internal/services/resolver/client_yandex.go, resolver_yandex.go, resolver.go и фактические обработчики ввода/предпросмотра. ParseURL сейчас возвращает тип и int64: UUID нельзя втиснуть в числовой ID. Точные вызовы и модель очереди сначала изучи.

## Реализация

1. Подтверди поддерживаемые форматы URL и протокол API по исходникам. Старый owner/kind и UUID — разные представления; не предполагай одинаковый endpoint.
2. Добавь подходящее представление ресурса, сохранив существующие album/track/artist сценарии и совместимость вызовов.
3. Из iframe извлекай только src. Нормализацию выполняй до общего URL-валидатора. Проверяй схему, hostname и длину; HTML не выполняй и не вставляй как доверенную разметку.
4. Используй существующий HTTP-клиент с context, timeout и proxy. Без токена запрашивай только поддерживаемые публичные данные. Обработай недоступность/приватность, пагинацию, пустой результат и частичные ответы.
5. Сохрани порядок и повторные вхождения треков. Ключ элемента очереди при необходимости отдели от каталожного ID.
6. Сохрани собственные метаданные каждого трека и Яндекс-ID. Не подменяй альбом названием плейлиста.
7. Проверь, не перезаписывают ли общие метаданные релиза поля треков при предпросмотре, постановке в очередь, восстановлении и тегировании. Исправь только необходимые места.
8. Покажи число полученных/пропущенных треков. Используй существующий выбор источников; импорт не должен менять ручной выбор или запускать скачивание.
9. Если API невозможно подтвердить, зафиксируй точный пробел вместо выдуманного рабочего endpoint.

## Приёмка

Mock-тесты форматов URL/iframe, старых типов ресурсов, пагинации, повторов, отсутствующих треков, malformed JSON, 401/403/404/451/429, отмены и похожих чужих доменов. Подтверди сохранение разных альбомов треков в очереди и итоговых тегах. При изменении UI используй применимые навыки дизайна и проверь вставку → предпросмотр → очередь на desktop/mobile. Не реализуй прямую загрузку Яндекса и тексты в рамках этой задачи.
