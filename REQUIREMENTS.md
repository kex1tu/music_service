# Требования к Music Downloader & Tag Manager

Music Manager — персональный веб-сервис для загрузки музыки, ведения файловой медиатеки и воспроизведения. Основной сценарий — найти релиз, выбрать дорожки и версии, проверить результат, отредактировать теги и принять файлы в медиатеку.

Документ объединяет [правила проекта](AGENTS.md), [описание сервиса](README.md), [руководство пользователя](USERGUIDE.md), [архитектуру](Architecture.md), [контракты API](API.md), [функции и регрессии из журнала разработки](PROGRESS.md), [результаты аудита безопасности](SECURITY_AUDIT_REPORT.md) и [шаблон конфигурации](.env.example). Статус реализации ведётся в журнале разработки. Мобильная переработка из [предложенного плана](plan.md) выделена отдельно.

- **Основной режим** охватывает локальную медиатеку, очередь, загрузчик, редактор, аудит и плеер.
- **Интеграции** принимаются для поддерживаемых сценариев при наличии доступа, учётных данных и системных утилит. При недоступности поставщика сервис показывает причину и сохраняет возможность продолжить работу с медиатекой.
- **Дополнительные режимы** включают торренты, радио, Navidrome и радар. Каждый режим можно принимать отдельно с его настройками и зависимостями.

При уточнении требований приняты следующие решения. Повторная загрузка сохраняет исходник до проверки замены. Оценки качества и цензуры показывают степень уверенности и требуют ручной проверки в неоднозначных случаях. Порог сопоставления целого релиза допускает отдельный поиск оставшихся дорожек. Численные цели производительности требуют согласованного профиля нагрузки. Эти уточнения задают целевое поведение, которое ещё предстоит сопоставить с реализацией. Исторические документы сохраняют роль источников контекста, при расхождении применять уточнения этого перечня с соблюдением инвариантов AGENTS.md.

## 1. Платформа и хранение

- **SYS-01.** Сервер на Go с Chi поставляется одним статическим бинарником `bin/music-manager` со встроенными шаблонами и статическими ресурсами. Версию Go для сборки задаёт [go.mod](go.mod). Целевая среда — Linux с `systemd`. Для развёртывания сохраняются ограничения Pure Go, Zero-Python, Zero-Node.js и No Docker из `AGENTS.md`.
- **SYS-02.** Загрузчик использует системные `yt-dlp` и `ffmpeg` с `libmp3lame`. Для торрент-режима нужен `aria2c`, для распознавания по аудио — `songrec`. Поставка Go-приложения и установка внешних инструментов описываются отдельно. Для полного режима YouTube задокументировать установку автономной сборки `yt-dlp` и компонентов EJS с поддерживаемым JS-движком, совместимым с ограничениями проекта. [Руководство yt-dlp EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS)
- **SYS-03.** Веб-интерфейс использует HTML, Alpine.js и Tailwind через CDN, встроенные SVG Google Material Symbols и Go-шаблоны без сборки. Для среды развёртывания требуется доступ браузера к используемым CDN. Общее состояние интерфейса ведётся в Alpine, сетевые обращения проходят через общий клиент API, прогресс загрузки обновляется неблокирующим опросом.
- **SYS-04.** Источник истины для музыкальных файлов и тегов — `MUSIC_DIR` и ID3. Pure Go SQLite в режиме WAL хранит индекс, кэш, очередь и служебные данные. База размещается на локальной файловой системе. Перестроение индекса сохраняет очередь, пользовательские настройки радара и историю радио. [Документация SQLite WAL](https://www.sqlite.org/wal.html)
- **SYS-05.** Организовать код по функциональным модулям с регистрацией маршрутов, общими HTTP-хелперами и явными зависимостями. Сборка приложения в `cmd/server/main.go` ограничивается конфигурацией, внедрением зависимостей и запуском. Публичные контракты сохраняются при внутренней реорганизации. [Спецификация модулей и тестового окружения](docs/superpowers/specs/2026-10-15-vertical-slices-testkit-architecture-design.md)

## 2. Источники, загрузки и очередь

| Источник | Требуемые возможности и условия |
|---|---|
| YouTube / YouTube Music | Треки и плейлисты, поиск аудио и альтернатив, поиск официального альбома и его треклиста в YouTube Music. Поддерживать гостевую попытку и работу с cookies при необходимости. Для недоступного контента показывать причину и доступные альтернативы. |
| SoundCloud | Треки, плейлисты, альбомы и сеты. Находить кандидатов целого релиза, дозапрашивать полные данные дорожек по ID и убирать дубли выдачи. Веб-эндпоинты и обновление `client_id` относятся к интеграции, зависящей от доступности платформы. |
| Deezer | Разворачивать короткие ссылки, получать каталог, дискографию, треклист, обложки, ISRC и соавторов. При недоступности метаданных пробовать iTunes. Для аудио подбирать отдельный источник. |
| Яндекс Музыка | Импорт треков, альбомов и дискографий, поиск метаданных и обложек. Прямая загрузка при наличии пригодного OAuth-доступа. Поддерживать настроенный прокси и понятную диагностику HTTP 451. |
| Spotify / Apple Music | Импорт поддерживаемых ссылок, треклистов, метаданных и обложек в пределах доступных данных. Для Spotify поддерживать официальный режим с учётными данными приложения и пагинацией, где доступ разрешён. |
| BitTorrent | При включённом режиме принимать `.torrent` и magnet-ссылки, применять ограничения размера и ожидания, показывать прогресс и передавать пригодные аудиофайлы в общий пайплайн. |

- **DL-01.** Принимать одиночные и пакетные ссылки, синглы, альбомы, EP и плейлисты. Показывать дискографию артиста и давать выбрать нужные релизы. Поддерживать автоматическое определение источника.
- **DL-02.** В Pre-Flight показывать треклист, новые дорожки, существующие треки с кандидатом на улучшение и имеющиеся треки с высоким битрейтом. По умолчанию выбирать новые дорожки и кандидатов на улучшение. Поддерживать ручной выбор, фильтры и предупреждение о дубликате сингла. При пустом выборе действие загрузки недоступно. Результат предварительного поиска можно использовать повторно в пределах срока его актуальности.
- **DL-03.** Сопоставлять треки по названию, артисту, длительности и признакам версии. Нормализовать технические суффиксы и Topic-каналы, извлекать соавторов и учитывать официальные источники. Случайные каверы, клипы с изменённой аудиодорожкой, караоке, live и ускоренные версии отсеивать при поиске студийного оригинала. Явно запрошенные ремиксы и другие версии сохранять. Статус совпадения показывать после получения пригодной ссылки на аудио.
- **DL-04.** Для релиза от двух дорожек искать цельные кандидаты YouTube Music и SoundCloud. Сравнивать дорожки по названиям и длительности, сопоставляя пары один к одному. Базовый порог принятия кандидата — 85% позиций целевого треклиста, с разницей длительности до 12 секунд для сопоставленной пары. Оставшиеся позиции искать отдельно. При результате ниже порога перейти к поштучному поиску. Не найденные позиции показывать пользователю.
- **DL-05.** Для отдельного трека предлагать альтернативные версии, предпрослушивание и ручную ссылку. Для релиза предоставлять выбор источника из очереди, аудита неполных альбомов и Puddletag, сравнение двух треклистов и ручное переназначение дорожек. Сохранять выбранный источник и перезапускать затронутые загрузки. При недоступности, ограничении региона или DRM показать причину и предложить пригодную альтернативу. При автоматической смене источника явно отобразить её в задаче.
- **DL-06.** Учитывать Clean/Explicit и риск цензуры как сигналы ранжирования. Повышать приоритет вероятного оригинала SoundCloud для русскоязычных релизов и официального студийного источника для зарубежных релизов с учётом других признаков совпадения. Неопределённая версия должна иметь явный статус. При наличии LRC предлагать до трёх Quick-Listen фрагментов с переходом по таймкоду и автопаузой.
- **DL-07.** Загружать и конвертировать асинхронно с отменой и таймаутами. Выходной формат — MP3 320 kbps CBR / 44,1 кГц. Очищать метаданные исходного контейнера перед записью ID3. Кодек, битрейт и частотный срез исходника показывать как отдельную приблизительную оценку. Для статуса улучшения нужны данные о новом источнике, одного выходного битрейта недостаточно.
- **DL-08.** Хранить очередь и результаты задач в SQLite, восстанавливать их при перезапуске и сортировать стабильно. Показывать этапы, монотонный прогресс активной попытки по дорожкам и релизу, состояние ошибок и ожидающие задачи. Поддерживать отмену, повтор, удаление и пакетную очистку завершённых задач. По умолчанию обрабатывать два релиза параллельно. Пределы сопоставления и обработки дорожек настраиваются отдельно.
- **DL-09.** Изолировать временные файлы по задачам в `tmp_downloads/{job_id}/`, очищать их по настроенному сроку хранения и давать слушать готовые дорожки до приёмки. Принимать один или все готовые релизы в медиатеку через органайзер либо открывать их в Puddletag. В пакетном редакторе сохранять группировку по релизам. Убирать из очереди только успешно принятые задачи.
- **DL-10.** Повторно скачивать трек или релиз по закреплённому источнику, каталожному идентификатору либо новому поиску. При замене сохранять текущие файлы до получения и проверки результата. Если загрузка отменена, источник не найден или обработка прервана, исходная запись остаётся доступной. Замену выполнять после подтверждения пользователя.

## 3. Теги, тексты, файлы и аудит

- **LIB-01.** Читать и записывать теги нативным Go-движком. Запись — ID3v2.4 UTF-8 с `\x00` для нескольких артистов, авторов альбома и жанров, APIC для фронтальной обложки, TRCK и TPOS для дорожек и дисков. Убирать конфликтующие поля `TXXX`. Сохранять значимые части имени артиста, включая числовые префиксы.
- **LIB-02.** Нормализовать жанры и согласовывать Artist и Album Artist, сохраняя гостевых артистов и индивидуальные составы соавторов на дорожках. Поддерживать совместимый с Navidrome вывод тегов, нормализацию подтверждённых синглов и корректировку прав доступа без изменений метаданных многотрековых релизов в режиме обработки синглов.
- **LIB-03.** Давать редактировать загруженные и локальные файлы через Puddletag. Поддерживать сетку, инспектор, несколько релизов, выделение и пакетное сохранение, сортировку, фильтрацию, пагинацию, горячие клавиши и предварительный просмотр изменений. Сохранять привязку правок к нужной дорожке при фильтрации и сортировке. Принимать скачанный релиз из редактора даже без ручных правок.
- **LIB-04.** Предусмотреть очистку названий, перенос `feat.` в поле исполнителя, поиск и замену по выбранным колонкам с поддержкой Regex и переименование «Теги → Файл» с безопасной обработкой имени. Для нумерации поддерживать поля номера дорожки и диска. Отдельные кнопки «Файл → Теги», «Регистр» и «Нумератор» исключены из перечня действий тулбара согласно блоку 90 журнала разработки.
- **LIB-05.** Сверять теги с Deezer и MusicBrainz, распознавать файлы через Shazam по аудиоотпечатку. Показывать предложенные теги, обложку и совпадения дорожек. Разрешать повторный автоматический подбор, ручное назначение пар один к одному и выбор применяемых данных. Для MusicBrainz поддерживать подключение OAuth 2.0, отображение статуса, обновление и отзыв локального подключения.
- **LIB-06.** Показывать встроенные и локальные обложки, извлекать APIC при отсутствии подходящего файла, загружать и удалять обложки. В галерее искать варианты Apple Music, Deezer, Яндекс Музыки и MusicBrainz Cover Art Archive, убирать дубли, показывать доступные размеры и фильтр по источнику. При явном выборе применять изображение к выбранным дорожкам или релизу и обновлять файлы обложек.
- **LIB-07.** Искать синхронизированные тексты через LRCLIB и обычные тексты через Genius в качестве резерва. Поддерживать поиск при загрузке, фоновую пакетную обработку, просмотр, вставку с определением формата, сохранение и удаление. Хранить тексты только во внешних `.lrc` и `.txt` рядом с аудио.
- **LIB-08.** Раскладывать альбомы по схеме `{Album} - {Album Artist}/{TrackNumber:02d}. {Title}.mp3`, синглы — `{Title} - {Artist}/01. {Title}.mp3`. Санитизировать имена, сохранять `cover.jpg` и при необходимости `{TrackBaseName}.jpg`. Переносить сопутствующие файлы вместе с треком и убирать опустевшие папки. При конфликте путей показывать конфликт или выбирать безопасный путь без молчаливой перезаписи.
- **LIB-09.** Показывать корень и вложенные папки, сохранять текущий каталог при обновлении. Поддерживать рекурсивный просмотр без отсечения на 2 000 треках, SQLite-кэш метаданных, полнотекстовый поиск с кириллицей и глобальный поиск `Ctrl+K`. Разрешать удаление файла, папки и выбранных дорожек с подтверждением и обновлением индекса. Корень медиатеки защищён от удаления.
- **LIB-10.** При старте и по запросу сканировать медиатеку, обновлять индекс по событиям файловой системы и учитывать ранее существовавшие файлы. После перемещения, удаления или сбоя между файловой операцией и записью в БД индекс должен приходить в согласованное состояние при восстановлении. Повтор операции не должен создавать дубликаты или приводить к потере исходных данных.
- **AUD-01.** Показывать сводку и списки дубликатов, неканонических путей, пропущенных текстов и обложек, неполных альбомов, проблем жанров и тегов, а также подозрительных цензурированных версий. Различать безопасное исправление, ручную проверку и информацию. Показывать отличия от каталога и степень совпадения. Безопасные локальные исправления должны работать при недоступных внешних API.
- **AUD-02.** Поддерживать одиночное и пакетное исправление путей, тегов и жанров, реорганизацию, фоновый сбор текстов с прогрессом и разбор дубликатов. При удалении показывать, какие файлы сохранятся и какие будут удалены. Одного совпадения названия и исполнителя для автоматического удаления недостаточно. Неоднозначные совпадения требуют выбора пользователя.
- **AUD-03.** Сверять неполный релиз с официальным треклистом, находить недостающие номера и ставить в очередь только нужные дорожки. В Puddletag показывать полный релиз из существующих и скачанных дорожек, подхватывать локальную обложку и сохранять возможность принять дозагрузку без ручного редактирования.

## 4. Воспроизведение, радио и радар

- **PLAY-01.** Запускать воспроизведение из файлов, поиска и очереди загрузки. В мини-плеере и отдельной вкладке поддерживать перемотку, громкость, отключение звука и горячие клавиши. В полной вкладке показывать обложку, сведения об аудио, спектр, очередь с перестановкой и удалением треков, повтор и перемешивание. В LRC подсвечивать текущую строку, поддерживать автопрокрутку и переход по строке. При наличии только TXT показывать несинхронизированный текст.
- **PLAY-02.** Отдавать аудиофайлы с HTTP Range, корректными ответами для полного, частичного и недопустимого диапазона. Поддерживать документированные маршруты потоков, метаданных, обложки, списка треков и алиас `/api/library/stream/{id}/chunks`. Для внешних плееров предусмотреть разрешённый способ доступа по токену.
- **RADIO-01.** Формировать «Мою Волну», станции по жанру и артисту. Учитывать избранное, историю, схожих исполнителей, разнообразие и ограничения повторов. Стартовая пропорция «Волны» — 45% любимых, 30% забытых и 25% открытий при наличии подходящего материала. Поддерживать M3U, актуальную информацию об играющем треке и MP3-вещание с ICY без перекодирования. При пустой выборке возвращать понятный ответ.
- **RADIO-02.** Поддерживать `GET`, `HEAD`, CORS и алиасы `.mp3` для непрерывных радиопотоков. При заданном `RADIO_STREAM_TOKEN` проверять доступ, включая поддерживаемые способы передачи токена и авторизованную сессию браузера. При пустом токене радиопоток открыт. Отразить это поведение в инструкции по развёртыванию.
- **RADIO-03.** При настройке Navidrome читать доступную статистику в режиме read-only, учитывать избранное и прослушивания, корректно сопоставлять пути. Через Subsonic API создавать станцию или обновлять уже зарегистрированную. Ошибка интеграции должна сохранять доступ к локальному плееру и остальным функциям.
- **RADAR-01.** Добавлять артистов из индекса и вручную. Управлять подписками, пользовательскими ссылками и автозагрузкой отдельно для артиста. Выполнять периодическую и ручную проверку с прогрессом и ограничением частоты запросов, показывать ленту, непрочитанные записи и пагинацию.
- **RADAR-02.** Сверять дискографии с медиатекой, находить пропущенные и новые релизы. Объединять дубли совместных релизов, учитывать кириллицу и альтернативные написания. Использовать известный год при неполной дате, отделять старые релизы и переиздания от новинок. Исключать имеющиеся релизы из новинок, отправлять выбранные в очередь и предотвращать повторную автозагрузку уже поставленного релиза.

## 5. Безопасность и публичные контракты

- **SEC-01.** Выполнять файловые операции через `PathSandbox.Resolve()` с ограничением доступа разрешённым корнем. - **API-01.** Поддерживать документированные HTTP-методы, маршруты и алиасы, формы JSON и multipart, коды и тела ошибок, пагинацию и Range. ## 6. Приёмка и качество

| Проверка | Ожидаемый результат |
|---|---|
| Загрузка и приёмка | Из Pre-Flight скачиваются только выбранные позиции. До подтверждения результат находится во временном каталоге. После приёмки теги, аудио и сопутствующие файлы доступны по каноническому пути и видны в поиске. Отмена и неудачный повтор сохраняют исходный файл. |
| Сопоставление источников | На тестовых треклистах есть точные, частичные и ложные совпадения, ремиксы и Clean/Explicit. Система корректно выбирает кандидата, обрабатывает непокрытые позиции и показывает неопределённость. Ошибки авторизации, геоблокировка, лимиты, DRM, таймаут и отсутствие кандидата дают различимую диагностику и предсказуемый результат. |
| Теги, аудит и бэкфилл | Сохраняются множественные значения и номера дисков, обложки обновляются, тексты остаются внешними. Пакетное редактирование после фильтрации меняет только выбранные записи. Дозагрузка объединяет в редакторе полный треклист. Неоднозначные дубликаты остаются доступны для ручного выбора. |
| Надёжность и защита | Проверяются обходы путей, перенаправления, повреждённые ID3, конкурентные обращения к SQLite, перезапуск очереди и сбой между обновлением файлов и индекса. Повтор завершённого действия оставляет данные в согласованном состоянии. |
| Плеер, радио и радар | Проверяются Range, перемотка и LRC, токены и методы радиопотоков, повторная регистрация станции без дубля, исключение скачанных и повторяющихся новинок, кириллические и совместные релизы. |
| Доступность | Цель — WCAG 2.2 AA для основных пользовательских сценариев. Сочетать автоматические проверки с ручной проверкой клавиатуры, фокуса, диалогов и скринридера. Проверять контраст, метки и понятные ошибки. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) |
| Масштаб и время ответа | На медиатеке более 2 000 треков обход и поиск не теряют результаты. При загрузке, аудите и сканировании интерфейс сохраняет управление и показывает состояние. Численные цели по задержке и ресурсам фиксируются после определения профиля сервера, размера коллекции, конкурентности и метода замера. Исторические замеры из журнала остаются результатами отдельных прогонов. |

Перед выпуском выполнить `go test -v ./...`, `go test -race ./...` и `go build -ldflags="-s -w" -o bin/music-manager cmd/server/main.go`. Использовать изолированные песочницы, временную SQLite, заглушки внешних HTTP-сервисов, регрессионные тесты и фаззинг ID3. Проверять Alpine-привязки, ключи `x-for` и сквозные сценарии API. Браузерные проверки запускать отдельным инструментом без npm и зависимостей в рабочем сервисе. Обновлять `.env.example` при изменении конфигурации и `PROGRESS.md` по фактическим результатам. [Отчёт аудита](SECURITY_AUDIT_REPORT.md), [инструкции к браузерным тестам](scripts/playwright/README.md)

## Уточнения пользователя 2026-11-08: подбор источников и цензура

Эти решения заменяют исторические эвристики DL-06 о преимуществах площадок:
- Источник выбирается вручную при каждой загрузке, включая ранее сохранённые
  привязки. Альтернативы не применяются автоматически при ошибке потока.
- Политика версии: как в релизе (default), предпочитать без цензуры, предпочитать
  clean. Совместимость записи обязательна независимо от политики.
- Цензура: любые намеренные заглушки, запикивания, вырезания и замены слов.
  Приоритет тем наркотиков и суицида не ограничивает поиск остальными темами.
- Аудит медиатеки (11000 треков, далее около 2000/месяц) только читает MP3/LRC;
  сохраняет подозрения и ручные решения отдельно, не исправляет файлы сам.
- Облачный этап необязателен, бюджет регулярной эксплуатации 0; нет платного
  fallback. Квоты и доступ должны быть настроены у провайдера отдельно.
- До пилота результаты — помощь для прослушивания, без гарантий обнаружения
  всех изменений или подтверждения отсутствия цензуры во всём треке.
